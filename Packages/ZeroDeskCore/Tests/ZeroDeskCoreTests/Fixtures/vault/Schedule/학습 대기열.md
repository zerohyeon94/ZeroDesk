## 2026-11 · 시스템 전체 한 바퀴

팀 3명이 전체를 함께 관리하므로, 먼저 **모든 구성 요소를 한 번씩** 훑는다. 데이터가 흐르는 순서(장비 안 → 장비↔서버 → 서버 → 화면 → 영상 → 배포)를 따른다. 깊이 파는 것은 12월 이후 각 달의 몫이다.

### 0. 전체
- [ ] 엣지-중앙 서버 구조: 장비 안의 AI 엔진·에이전트와 중앙 서버의 역할 나누기 → [[Learning/개념/2026-11-03 엣지-중앙 서버 구조|엣지-중앙 서버 구조]]
- [ ] 감시 시스템은 누가 어떻게 쓰나: 운영자, 관리자, 설치 담당자의 하루
- [ ] 이벤트 하나의 업무 흐름: 감지 → 알림 → 확인 → 조치 → 기록
- [ ] 오탐과 미탐의 비용: 운영자 피로와 놓친 사고
- [ ] 에이전트로 낯선 코드베이스 파악하기: 구조 요약을 요청하고 맞는지 확인하기

### 1. 장비 안
- [ ] 소리 이벤트 감지 기초: dB, 이동 평균 기준선(EWMA), 상대값 트리거
- [ ] 온디바이스 추론 기초: TensorFlow Lite 모델이 ARM 장비에서 도는 방식
- [ ] gRPC 스트리밍: 서버 스트림과 클라이언트 스트림, keepalive
- [ ] Protocol Buffers와 코드 생성: 계약 하나로 Go와 C++ 코드를 만드는 법
- [ ] 프로세스 감시: systemd watchdog과 감시자(launcher) 패턴
- [ ] 현장 설치 조건: 전원, 네트워크, 주변 소음이 성능을 바꾸는 이유

### 2. 장비 ↔ 서버
- [ ] SSE와 pull 방식 수집: 서버가 장비에 붙어서 이벤트를 가져오는 이유
- [ ] Go 동시성 패턴: 채널 팬아웃과 느린 수신자 버리기(drop)
- [ ] 서버 간 인증: 오래 쓰는 토큰을 짧은 JWT로 교환하기

### 3. 서버
- [ ] 사용자 인증: access JWT, refresh 토큰, 서버 세션으로 즉시 무효화하기
- [ ] PostgreSQL 마이그레이션(up/down)과 테이블 파티셔닝
- [ ] 프로세스 내장 워커풀과 배치 작업: 왜 서버를 하나만 띄우는가

### 4. 화면
- [ ] go:embed: 웹 화면을 Go 바이너리 하나에 넣기
- [ ] Redux Toolkit과 RTK Query: 서버 데이터를 화면 상태로 다루기
- [ ] pnpm 워크스페이스와 Vite alias: 공유 패키지를 소스째 가져오기

### 5. 영상
- [ ] ONVIF·WS-Discovery·RTSP: IP 카메라를 찾고 영상을 받기
- [ ] WebRTC 연결 과정: SDP offer/answer와 ICE
- [ ] NAT와 STUN·TURN: 직접 연결이 안 될 때 돌아가는 길
- [ ] SFU: 영상 하나를 여러 시청자에게 나눠 주기

### 6. 배포
- [ ] 크로스 컴파일: Go의 GOOS·GOARCH와 C++ 툴체인
- [ ] tus: 끊겨도 이어 올리는 업로드
- [ ] 펌웨어 패키지 신뢰: 서명(Ed25519), 암호화(AES-GCM), 인증서 체인
- [ ] OTA 롤백: 백업과 sentinel 파일로 정상 부팅 판정하기
- [ ] 같은 망의 장비 찾기: UDP 브로드캐스트와 L2 프레임
