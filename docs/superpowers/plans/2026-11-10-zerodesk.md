# ZeroDesk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** iCloud의 Obsidian 볼트를 읽기 전용으로 보여 주는 iPad 우선 SwiftUI 앱. 홈(학습 게이지·주요 일정), 2단 학습 화면, 파일 종류별 읽기 방식.

**Architecture:** 파일 형식 해석은 전부 로컬 Swift 패키지 `ZeroDeskCore`에 두고 Mac에서 `swift test`로 TDD 한다. 앱 타깃 `ZeroDesk`는 볼트 접근(보안 범위 북마크, iCloud 내려받기), 상태(`VaultStore`), SwiftUI 화면만 맡는다. 마크다운은 swift-markdown으로 AST를 만들고 블록 렌더러는 직접 쓴다(절 나누기·줄바꿈·코드 블록 가로 스크롤을 직접 통제하기 위해).

**Tech Stack:** Swift 6, SwiftUI, iOS/iPadOS 18+, Swift Testing, [swift-markdown](https://github.com/swiftlang/swift-markdown), XcodeGen(`project.yml`, Jday 관례).

**Spec:** `docs/superpowers/specs/2026-11-10-zerodesk-design.md` — 각 작업은 스펙의 절 번호를 단다. 실행자는 둘 다 읽는다.

## Global Constraints

- 앱은 볼트에 쓰지 않는다. 쓰기 API(`write`, `removeItem`, `moveItem`, `createFile`)를 볼트 URL에 호출하는 코드가 없어야 한다.
- 앱은 네트워크 요청을 하지 않는다(`URLSession` 사용 없음). 외부 링크는 시스템 브라우저로 넘기기만 한다.
- 최소 iOS 18.0, `TARGETED_DEVICE_FAMILY: "1,2"`, bundle id `com.zerohyeon.zerodesk`, `DEVELOPMENT_TEAM: 5G6N83PM9C`(Jday와 같은 팀; TestFlight 단계에서 사용자 확인).
- 화면 글은 한국어. 문구는 스펙 그대로: "이번 달 대기열이 아직 없음", "주요 일정 파일이 아직 없음", "형식을 읽지 못함 · 파일 열기", "읽지 못한 줄 N개", "오늘 개념 없음", "파일을 찾지 못함", "iCloud에서 받는 중".
- 테스트 자료(Fixtures)에 볼트 `회사/` 내용을 넣지 않는다.
- 홈 상수: 다가오는 일정 최대 8, 최근 발표 14일(오늘 − 13일 이후)·최대 5, 하루 속도 소수 한 자리 반올림, 남은 날은 오늘 포함.

## Review Focus

- 볼트 폴더 권한이 끊김(북마크 stale·폴더 이동) → 앱이 죽지 않고 "볼트 폴더 다시 고르기" 화면으로 간다. (Task 6 테스트)
- iCloud 파일이 아직 안 내려옴·내려받기가 30초 넘게 안 끝남 → "iCloud에서 받는 중" 뒤 오류 문구와 다시 시도 버튼. (Task 6 테스트)
- 월 경계: 새 달 1일인데 대기열에 그 달 절이 없음, 말일에 남은 날 = 1. (Task 3 테스트)
- 위키 링크: 같은 이름 파일 여러 개, `#제목` 붙음, 표 안의 `\|`, 대상 없음. (Task 4 테스트)
- 이상한 md: 빈 파일, `##`가 하나도 없는 파일, 앞머리만 있는 파일, 코드 블록 안 `#` 줄. (Task 5 테스트)
