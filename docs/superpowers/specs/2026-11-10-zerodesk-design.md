# ZeroDesk 설계

> 2026-11-10 · 상태: 사용자 승인 (9장 "내가 정한 것" 포함) · 앱 이름 "ZeroDesk"는 가명

## 1. 무엇을, 왜

사용자는 iCloud에 있는 Obsidian 볼트(`zerohyeon-labs`)의 md 파일로 매일 학습한다. 파일은 ZeroSync 봇이 Mac에서 쓰고(개념 노트, Daily, 대기열 표시), 사용자는 iPad에서 읽는다. 지금은 Obsidian으로 읽는데 세 가지가 불편하다.

1. **로딩:** 켤 때 기다려야 한다.
2. **한 번에 파일 하나:** 학습이 얼마나 진행됐는지(대기열)와 오늘 노트를 함께 볼 수 없다.
3. **빽빽한 글:** 줄을 바꿔 써도 화면에서 붙고, 주제(절) 사이 경계가 약해서 긴 노트를 읽기 힘들다.

ZeroDesk는 이 볼트를 **읽기만 하는** iPad·iPhone 앱이다. 홈에서 학습 진행 상태와 주요 일정을 먼저 보여 주고, "학습 파일" 탭에서 두 파일을 나란히 펴 놓고 읽는다.

봇과의 관계는 "ZeroSync가 쓰고, ZeroDesk가 읽는다"이다. 앱은 볼트에 아무것도 쓰지 않는다 단 하나의 예외는 Pencil 필기다(2026-11-11 추가): 노트 파일은 그대로 두고, 앱 전용 숨김 폴더 `.zerodesk/필기/<노트 경로>.ink.json`에만 쓴다. 숨김 폴더라 Obsidian 목록에 보이지 않고 iCloud로 기기 사이에 동기화된다.

## 2. 목표, 하지 않는 것, 실패로 보는 것

**목표**
- 앱을 열면 학습 게이지와 다가오는 일정이 바로 보인다.
- 대기열과 개념 노트를 iPad에서 나란히 본다.
- 긴 개념 노트가 절 단위로 또렷하게 나뉘어 읽힌다.
- `[[링크]]`를 누르면 그 노트로 가고, 돌아올 수 있다.
- iPad가 먼저다. iPhone은 같은 기능을 한 열로 보여 준다.

**하지 않는 것 (이번 범위)**
- 편집, 체크박스 누르기, 볼트에 쓰기
- 검색, 그래프 보기, 태그 (내 판단: 요청되지 않음)
- 홈 화면 위젯 (다음 후보)
- 봇 DB·Discord 연결. 학습 완료는 봇이 대기열에 `[x]`로 옮겨 적은 것만 센다(하루 늦게 반영됨을 받아들인다)
- 인터넷에서 일정·뉴스를 직접 받아오기. 일정은 볼트 파일에서만 읽는다
- App Store 공개. TestFlight 내부 테스트로 본인 기기에만 설치한다

**실패로 보는 것 (동작해도)**
- Obsidian처럼 켤 때 기다리게 하는 것
- 글이 여전히 붙어 보이는 것, 텍스트 그림이 줄바꿈으로 깨지는 것
- 실적 발표에 금액·주가·해설이 붙는 것. 볼트 규칙(AGENTS.md "투자·시장 브리핑을 만들지 않는다") 때문에 날짜와 이름만 보여 준다
- 볼트 파일을 바꾸거나 지우는 것

## 3. 환경과 제약

- 볼트: iCloud Drive의 Obsidian 컨테이너 안 `zerohyeon-labs` 폴더. 다른 앱 컨테이너라 앱이 직접 경로로 열 수 없다.
- 개발: Mac, Xcode 27.2, SwiftUI. 유료 Apple 개발자 계정 있음. 배포는 TestFlight 내부 테스트.
- 코드 위치: `~/Developer/ZeroDesk` (이 저장소). 볼트에는 앱 코드를 두지 않는다.
- 같은 사용자의 다른 앱(GagaeSsi, Jday)이 `~/Developer`에 있다. 프로젝트 구성 관례는 그쪽을 참고해도 된다.
- 볼트에는 `회사/` 폴더가 있다(git 제외, 회사 정보). 앱은 기기 안에서 읽기만 하므로 보여 줘도 되지만, 내용을 앱 밖(로그, 분석, 서버)으로 보내지 않는다. 앱은 네트워크 요청을 하지 않는다.

## 4. 화면

위쪽 탭 세 개: **홈 · 학습 파일 · 설정**. 사용자가 본 시안의 배치는 아래와 같다 (iPad 가로).

```text
홈                                         학습 파일
┌──────────[ 홈 | 학습 파일 | 설정 ]─────────┐  ┌──────────[ 홈 | 학습 파일 | 설정 ]─────────┐
│ ┌ 11월 · 주제 ─────┐ ┌ 다가오는 일정 ───┐ │  │ 학습 대기열 · 11월 ⇄ │ 개념 노트 제목  ☰ ⇄  │
│ │ 0 / 29 개념      │ │ 11/20 제목 [실적]│ │  │ 0. 전체      0 / 5   │ ① ② ③ ④ ⑤ ⑥   3 / 6 │
│ │ ████░░░░░░░░     │ │ 12/02 제목 [행사]│ │  │ ▬▬▬▬▬▬▬▬▬▬           │ ──────────────────── │
│ │ 남은 20일 · 1.5개│ │ 3월  SQLD [시험] │ │  │ ● 지금 하는 항목     │ 1. 한 문장으로       │
│ └──────────────────┘ │ ...         D-10 │ │  │ ○ 다음 항목          │ 본문 …               │
│ ┌ 1년 목표 (한 줄) ┐ │ ── 최근 발표 ──  │ │  │ 1. 장비 안   0 / 6   │ 다음: 비유 →         │
│ └──────────────────┘ │ 11/09 제목 [기술]│ │  │ ...                  │ ──────────────────── │
│ ┌ 오늘 개념 (링크) ┐ └──────────────────┘ │  │                      │ 2. 비유 …            │
└────────────────────────────────────────────┘  └────────────────────────────────────────────┘
```

- 홈: 왼쪽 열이 학습 상태 카드 셋(게이지, 1년 목표, 오늘 개념), 오른쪽 열이 일정 카드 하나. 왼쪽:오른쪽 폭은 약 1:1.15
- 학습 파일: 각 칸 머리에 파일 이름, ⇄(파일 바꾸기), 오른쪽 칸에는 ☰(목차). 절 표시줄은 오른쪽 칸 머리 바로 아래에 고정

### 4.1 홈

iPad 가로 기준 2열. iPhone은 한 열로 쌓는다(게이지 → 일정 → 오늘 개념).

**왼쪽: 학습 상태**
- 이번 달 주제와 게이지: "11월 · 시스템 전체 한 바퀴", 큰 숫자 "0 / 29 개념", 막대
- 그 아래 한 줄: 이달 남은 날 수와 "하루 N개 속도 필요"(남은 항목 ÷ 남은 날, 소수 한 자리). 남은 날은 오늘을 포함한다(내 판단)
- `주요 일정.md`가 없으면 일정 카드에 "주요 일정 파일이 아직 없음"을 보여 준다
- 1년 목표: 월별 목표 파일의 `1년 목표:` 한 줄을 그대로 보여 준다. 현재 달성 수는 어느 파일에도 없으므로 숫자 진행은 만들지 않는다
- 오늘 개념: 누르면 학습 파일 탭의 오른쪽 칸에 그 노트를 연다

**오른쪽: 다가오는 일정**
- `Schedule/주요 일정.md`의 "다가오는 일정"을 오늘 이후 날짜순으로, 최대 8개
- 한 줄: 날짜(월/일), 제목, 종류 이름표(시험·기술·실적·행사, 색으로 구분), D-day. 월까지만 아는 날짜는 D-day 대신 "N월"과 "추정"
- 그 아래 "최근 발표": 같은 파일의 "최근 발표"에서 최근 14일 것만, 최대 5개

### 4.2 학습 파일

**iPad: 2단.** 기본 배치는 왼쪽 학습 대기열, 오른쪽 오늘 개념 노트. 각 칸 위에 "파일 바꾸기" 버튼이 있어 아무 md나 고를 수 있다. 마지막 배치를 기억한다.
- 왼쪽 칸에서 링크를 누르면 오른쪽 칸에 연다.
- 오른쪽 칸에서 링크를 누르면 오른쪽 칸 안에서 이동하고, 뒤로 가기로 돌아온다.
- (내 판단) 칸 비율은 왼쪽 약 40%, 오른쪽 60%.

**iPhone: 한 칸.** 파일 목록 → 파일 읽기로 넘어간다.

**파일 바꾸기 / 파일 목록:** 맨 위에 자주 쓰는 곳 세 개(`Learning/개념`, `Daily`, `Schedule`)를 최근 수정 순으로, 그 아래 "전체 폴더"로 볼트 전체를 탐색. 숨김 폴더(`.`으로 시작)는 보이지 않는다.

### 4.3 설정

- 볼트 폴더 다시 고르기
- 마지막 갱신 시각과 "지금 새로고침"

## 5. 파일 종류별로 보여 주는 방식

경로로 정한다.

### 5.1 학습 대기열 (`Schedule/학습 대기열.md`)
- 진행 보기로 보여 준다: 이번 달 `##` 절 안의 `###` 묶음마다 "완료 / 전체"와 작은 막대, 그 아래 항목 목록
- 항목: `[x]`는 완료 표시, `→ [[...]]` 링크가 붙은 미완료 항목은 "지금 하는 중"으로 강조, 누르면 그 노트를 연다
- 다음 달 이후 절은 접어 둔다
- 진행 보기 오른쪽 위에 "원문 보기"로 일반 읽기 방식 전환

### 5.2 Daily (`Daily/`)
- `##` 절마다 테두리 상자(카드). 절 6~7개, 각 3~6줄 목록이라 보고서처럼 보인다
- iPad 가로에서는 카드 2열

### 5.3 개념 노트 (`Learning/개념/`)와 나머지 모든 md
길게 읽는 방식. 상자로 감싸지 않는다(한 절이 90줄을 넘는 경우가 있어 상자가 화면 몇 장 크기가 된다).
- **절 구분:** `##` 절 사이를 크게 띄우고 구분선, 제목 앞에 번호. `###`는 한 단계 작은 제목
- **절 표시줄:** 화면 위에 절 이름을 짧게 나열하고 지금 읽는 절을 강조, 누르면 그 절로 이동, "3 / 6" 표시. 스크롤하는 동안 계속 보인다
- **다음 절 버튼:** 각 절 끝에 "다음: <절 이름>"
- **이어 읽기:** 파일마다 마지막으로 읽던 절을 기억하고 그 절에서 연다
- **줄바꿈:** 문단 안에서 한 번 바꾼 줄도 화면에서 줄이 바뀐다(마크다운 기본은 같은 문단으로 붙임). 코드 블록, 표 안에는 적용하지 않는다
- **문단·줄 간격:** 넉넉하게. 본문 한 줄 폭을 제한해 iPad 가로에서 줄이 너무 길지 않게
- **강조 문단:** 굵은 글씨로 시작하는 문단(예: "**비유가 틀리는 지점:** …")과 `>` 인용은 옅은 배경
- **코드 블록·텍스트 그림:** 고정폭 글꼴, 줄바꿈 없음, 블록 안에서 가로 스크롤. 상자는 여기에만 쓴다
- **목차에서 제외:** 코드 블록 안의 `#`로 시작하는 줄은 제목이 아니다

방식은 위아래 스크롤로 정했다. 좌우 넘김은 쓰지 않는다(절 길이가 9~88줄로 고르지 않고, 코드 블록 가로 스크롤과 동작이 겹친다).

### 5.4 공통으로 그려야 하는 마크다운
제목, 문단, 굵게·기울임, 목록(중첩 포함), 체크박스 목록(읽기 전용), 인용, 코드 블록, 표, 가로줄, 외부 링크, 위키 링크, 그림 넣기.
- 표는 넓으면 가로 스크롤
- 그림 넣기 `![[Assets/파일.png]]`: png·jpg는 폭에 맞춰 보여 주고 누르면 확대. svg(옛 노트에 많다)는 볼 수 있으면 보여 주고, 아니면 파일 이름 링크로 대신한다(빌더 판단)
- 앞머리(frontmatter)가 있으면 본문에서 숨긴다

## 6. 위키 링크

형식: `[[대상]]`, `[[대상|보이는 글]]`, `[[대상#제목]]`, `![[대상]]`(넣기).
- 찾는 순서: (1) 볼트 기준 경로로 정확히 일치(`.md` 생략 허용) (2) 파일 이름만으로 일치. 여러 개면 경로가 가장 짧은 것
- `#제목`이 있으면 그 절로 스크롤
- 못 찾으면 회색 글자로 보여 주고 누르면 "파일을 찾지 못함"
- `|` 앞뒤가 표 안에서 `\|`로 이스케이프된 경우도 처리한다(월별 목표 등에서 쓰임)

## 7. 홈이 읽는 파일과 형식 (봇과의 약속)

앱은 아래 형식을 기준으로 숫자를 센다. 형식이 바뀌면 앱도 고쳐야 한다. 형식을 못 읽으면 앱은 멈추지 않고 그 카드에 "형식을 읽지 못함 · 파일 열기"를 보여 준다.

### 7.1 `Schedule/학습 대기열.md` (기존 파일)
- 이번 달 절: `## YYYY-MM · 주제` 줄. 오늘 날짜의 연-월과 같은 것
- 묶음: 그 아래 `### 이름`
- 항목: `- [ ] 내용` 또는 `- [x] 내용`. 개수 = 이번 달 절 안의 항목 수, 완료 = `[x]` 수
- 오늘 개념: 이번 달 절에서 `→ [[...]]`가 붙은 항목 중 마지막 미완료 항목의 링크. 없으면 "오늘 개념 없음"
- 이번 달 절이 없으면(월초 봇 갱신 전) 게이지 대신 "이번 달 대기열이 아직 없음"

### 7.2 `Schedule/월별 목표 (2026-11 ~ 2027-10).md` (기존 파일)
- `> 1년 목표:`로 시작하는 줄만 읽는다. 파일 이름은 `Schedule/월별 목표 (`로 시작하는 파일 중 가장 최근 것

### 7.3 `Schedule/주요 일정.md` (새 파일)
ZeroSync 봇이 매일 갱신한다. 봇 작업 전에는 사용자가 손으로 만든 예시로 앱을 확인한다. 이 형식은 ZeroDesk 쪽에서 정하고, 봇 작업이 이 형식을 따른다.

```markdown
# 주요 일정

> ZeroSync 봇이 갱신한다. 실적 발표는 날짜와 회사 이름만 적는다.

## 다가오는 일정

- 2027-03 · 시험 · SQLD (추정)
- 2026-11-20 · 실적 · 회사 이름 분기 실적 발표
- 2026-12-02 · 행사 · 행사 이름
- 2027-06 · 시험 · 리눅스마스터 2급 (추정)

## 최근 발표

- 2026-11-09 · 기술 · 모델 이름 5.2 출시 · [출처](https://example.com)
```

- 한 줄 = `- 날짜 · 종류 · 제목` + 선택적으로 ` · [출처](URL)`
- 날짜: `YYYY-MM-DD` 또는 `YYYY-MM`(월만 아는 경우)
- 종류: `시험`, `기술`, `실적`, `행사` 중 하나. 모르는 종류는 `행사`처럼 보여 준다
- 제목 끝의 `(추정)`은 이름표로 보여 준다
- 순서는 자유. 앱이 정렬한다
- 읽지 못한 줄은 건너뛰고, 건너뛴 줄이 있으면 일정 카드 아래 작게 "읽지 못한 줄 N개"

**시험의 출처 (내 판단, 대화 중 바꿈):** 대화에서는 시험을 `자격증 일정.md` 표에서 직접 읽겠다고 했지만, 그 표의 "목표 회차" 칸은 "2027년 3월 회차", "2027-07", "2027년 3회 (예년 …)"처럼 자유 글이라 날짜로 읽기 어렵다. 그래서 홈 일정은 `주요 일정.md` 하나만 읽고, 시험도 봇이 `자격증 일정.md`에서 옮겨 적는다. 봇 작업 전에는 손으로 적는다.

### 7.4 볼트 쪽 후속 (승인 후, 별도 작업)
- 볼트 `AGENTS.md`에 "`주요 일정.md`와 대기열 형식을 바꾸면 ZeroDesk도 고친다"를 추가
- ZeroSync 저장소에서 `주요 일정.md` 갱신 작업 (출처 조사 포함). 이 문서 범위 밖

## 8. 볼트 접근과 속도

- **처음 실행:** 폴더 고르기 창에서 사용자가 `zerohyeon-labs`를 고른다. 앱은 접근 권한을 북마크로 저장해 다음부터 바로 연다. 권한이 끊기면(폴더 이동 등) 다시 고르라고 안내한다.
- **iCloud 내려받기:** iPad에는 파일이 이름만 있고 내용이 아직 안 내려온 상태일 수 있다. 열 때 내려받기를 요청하고 기다리며, 그동안 "iCloud에서 받는 중"을 보여 준다. 읽기는 파일 조정(coordinated read)으로 한다.
- **빠른 시작:** 앱을 켜면 지난번 색인(파일 경로·이름·수정 시각)과 홈 숫자를 먼저 보여 주고, 뒤에서 다시 훑어 갱신한다. 색인에는 파일 내용을 저장하지 않는다.
- **갱신 시점:** 앱이 앞으로 올 때, 설정의 새로고침, 학습 파일 목록을 아래로 당길 때.
- **목표 (내 판단):** 앱을 켜고 홈 숫자가 보이기까지 1초 안(지난 값 기준). 실제 iPad에서 확인한다.

**사용자가 정한 것**

**내가 제안하고 사용자가 승인한 것 (2026-11-10)**
